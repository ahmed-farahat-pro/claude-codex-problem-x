## What you'll learn

This is the lesson where Codex stops looking like a faster autocomplete and starts looking like a way to run a team of agents. **Cloud sandboxes** give each agent an isolated clone of your repo, so several can work at once without stepping on each other — which unlocks the strategy of trying multiple approaches to one hard problem and keeping whichever actually works. The **`/goal` workflow** persists an objective across sessions, so multi-day work doesn't restart from zero every morning. **Browser verification** lets an agent check what it built by actually looking at it, rather than asserting it works. And the **desktop App** is the control surface for all of it: several agents in flight, and you supervising rather than driving. You'll learn how to scope a goal so it survives a week, how to review parallel results without drowning, and where this genuinely beats one careful session.

---

## Key takeaways

- **Isolated sandboxes make parallelism real.** Each agent gets its own clone, so five simultaneous attempts don't collide.
- **Parallel exploration is a strategy, not a gimmick.** For a genuinely hard problem, several independent attempts often beat one long careful one.
- **`/goal` carries the objective across sessions** — the mechanism that makes multi-day work possible instead of a nightly restart.
- **Scope the goal like a spec.** A persistent objective with a fuzzy definition of done drifts further the longer it runs. → [core/03-scheduled-agents-concept.md](../core/03-scheduled-agents-concept.md)
- **Browser verification closes the loop.** An agent that can look at what it built catches what tests miss.
- **The App is a supervision surface.** Your job shifts from writing to reviewing — which is a real skill, and the bottleneck at this scale.
