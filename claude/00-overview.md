## What you'll learn

Claude's defining characteristic as an agent platform is *reach*: it shows up in the places work already happens rather than requiring the work to come to it. This lesson maps every surface and, more usefully, tells you which one to open for a given job. **Claude Code** is the terminal agent (also in the desktop app, on the web, and in IDEs) for anything repo-shaped. **Cowork** is the agent workspace for people who don't live in a terminal — the surface that makes Claude viable for a recruiter, an analyst, or a marketer. **Claude in Chrome** drives a real browser for the work that never had an API. **Excel and PowerPoint** put the agent inside the file formats most business output actually ships in. **Claude Tag** puts it in Slack, where requests already arrive. Understanding this map is what stops you from doing spreadsheet work in a terminal, or vice versa.

---

## Key takeaways

- **Claude Code** — terminal-native agent with subagents, hooks, and `CLAUDE.md` project config. The right surface for anything under version control. → [01-claude-code.md](01-claude-code.md)
- **Cowork** — the non-developer agent workspace, plus Scheduled Tasks for recurring work. This is why Claude is usually the answer for people without a repo. → [02-cowork-and-scheduled-tasks.md](02-cowork-and-scheduled-tasks.md)
- **Excel and PowerPoint** — agent work inside the Office suite. Finance, consulting, and ops deliverables live here, so the agent should too.
- **Claude in Chrome** — a real browser session under agent control, for the legacy portals and internal tools that will never expose an API.
- **Claude Tag (Slack)** — the agent where team requests already land, so nobody has to change where they ask.
- **Start with the surface, not the tool.** Match where the work physically happens; the capability is broadly the same underneath.
